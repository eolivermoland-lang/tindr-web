About

An original operating system, drawn from the Norwegian landscape.

Tindr is a desktop system for x86-64 and AArch64, written in Rust from an empty directory. It aims to be better than the systems we already have on a short list of measurable promises, not by looking like them.

  • Capabilities, not root.

    A task should only touch what it holds a handle to. That Ledger is planned for a later milestone. The idea already shapes the design.

  • A small kernel. Everything else restartable.

    Drivers and services will live in user space and be supervised by Hearth. A crash should restart a component, never the machine.

  • Discover, never assume.

    Hardware is found through ACPI and the device tree. The kernel does not hard-code machine addresses from a particular emulator.

  • Proof over claims.

    A feature is not done until an automated test proves it in QEMU on both architectures. Golden screenshots are compared with zero tolerance.

  • Norwegian from day one.

    UTF-8 everywhere. The letters æ, ø and å work in the font, in the keyboard plan, in file names and in sorting.

  • Own expression.

    Nordic, calm, sharp and fast. Design tokens live in one file. Light and dark mode are part of the system plan. No imitation of other desktops.

Some of these layers already exist. The later ones are planned, and are named here so the shape of the system is visible now.

  1. tindr-boot. A UEFI loader. Built.
  2. Hybrid kernel. Hardware layer, virtual memory, interrupts and time are in place. Tasks, Weaves, Gates and the Ledger are planned, with Weaves underway in M3.
  3. User-space drivers. Planned.
  4. Hearth and Registry. Planned.
  5. Unix layer. VFS, TindrFS, processes, TTY and sockets. Planned.
  6. Runtime. Our own libc and Rust runtime. Planned.
  7. Graphics. A vector library and a text engine already draw the boot and panic screens in the kernel. A compositor is planned.
  8. Desktop and apps. Planned.

Tindr boots through UEFI on x86-64 and on AArch64. The first target is QEMU, then a virtual machine on Apple silicon, then a physical PC. The same tests run on both architectures. One is not a port of the other.
