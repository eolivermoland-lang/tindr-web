Tindr 0.1-dev – x86-64 and AArch64

  • UEFI loader

    tindr-boot loads the kernel as an ELF file, exits boot services, and hands over the memory map, the framebuffer, and ACPI or a device tree. Hardware is discovered, never assumed from a fixed address.

  • Memory the kernel owns

    A physical frame allocator, a kernel heap, and our own page tables. Executable pages are not writable. Writable pages are not executable. That write xor execute rule is already in force.

  • Interrupts and time

    Exception vectors on both architectures, a local APIC calibrated against HPET, a Generic Interrupt Controller on AArch64, and a 1 kHz tick with a monotonic clock.

The official mark is two notched peaks, drawn as vectors so it stays sharp at any size. The typeface is Fjord Sans, designed by Oliver Torden in 2026, in Thin, Regular and Bold. Norwegian letters work from day one: æ, ø and å are first-class in the font, in file names, and in sorting.

The boot screen is a quiet sky, a far ridge, a near ridge with a line of glacier light, and the mark centred above them. That is the same landscape this site is built from.

Already in the kernel

  • Write xor execute on every page the kernel maps.
  • A fault is never silent. Unexpected exceptions show on the screen and over serial, with the real registers.
  • Memory maps and firmware tables come from the machine, not from baked-in addresses.

Planned

  • Capabilities instead of root: a task can only touch what it holds a handle to.
  • Drivers and services in user space, restarted by Hearth if they crash.
  • Sandboxing, no telemetry, no ads, no forced accounts, and updates that roll back on failure.
